# Local infrastructure

mynotes needs two services: **PostgreSQL** (source of truth) and **OpenSearch** (hybrid search index). Both run in Docker via `docker-compose.yml`; the mynotes application itself runs natively with `uv` (file watching doesn't work reliably through Docker bind mounts on macOS/Windows; see PLAN.md §7.8).

## Pinned versions

| Service | Image | Chosen on |
|---|---|---|
| PostgreSQL | `postgres:18.6` (newest stable major is 18) | 2026-09-24 |
| OpenSearch | `opensearchproject/opensearch:3.8.0` (newest stable 3.x) | 2026-09-24 |

Integration tests (testcontainers) must use the same tags. Upgrade by editing `docker-compose.yml` and this table together.

Notes:
- PostgreSQL 18 is required: migrations use `uuidv7()`.
- The PostgreSQL 18 image stores data under `/var/lib/postgresql/18/docker`, so the volume is mounted at `/var/lib/postgresql` (not `…/data` as in older images).
- OpenSearch runs with the security plugin **enabled** (HTTPS with a self-signed certificate, basic auth). Clients connect with `verify_certs: false` locally.
- Both ports are bound to `127.0.0.1` only; nothing is exposed to the network.

## Configuration (`.env`)

| Variable | Purpose | Default |
|---|---|---|
| `MYNOTES_COMPOSE_PG_PASSWORD` | Password of the `mynotes` Postgres user | (required) |
| `MYNOTES_COMPOSE_PG_PORT` | Host port for Postgres | 5432 |
| `MYNOTES_COMPOSE_OS_PORT` | Host port for OpenSearch | 9200 |
| `MYNOTES_COMPOSE_OS_HEAP` | OpenSearch JVM heap (`-Xms`/`-Xmx`) | 2g |
| `MYNOTES_OPENSEARCH_PASSWORD` | Initial password of the OpenSearch `admin` user; must be strong (≥ 8 chars, upper, lower, digit, special) or OpenSearch refuses to start | (required) |

The application connects with:
- `MYNOTES_PG_DSN=postgresql+psycopg://mynotes:<MYNOTES_COMPOSE_PG_PASSWORD>@localhost:<MYNOTES_COMPOSE_PG_PORT>/mynotes`
- `MYNOTES_OPENSEARCH_URL=https://localhost:<MYNOTES_COMPOSE_OS_PORT>`, `MYNOTES_OPENSEARCH_USER=admin`, `MYNOTES_OPENSEARCH_PASSWORD`

If a port is already taken on your machine, change `MYNOTES_COMPOSE_*_PORT` and the matching DSN/URL in `.env`.

The OpenSearch admin password is only applied when the data volume is created. Changing it later requires the OpenSearch security API, or deleting the volume (`docker compose down -v`, which **deletes the index**; it can be rebuilt from Postgres with `mynotes index rebuild`).

## Commands

```bash
docker compose up -d          # start (containers restart automatically unless stopped)
docker compose ps             # both should show "healthy" after ~1 minute
docker compose logs -f        # follow logs
docker compose stop           # stop, keep data
docker compose down           # remove containers, keep volumes (data)
docker compose down -v        # remove containers AND data volumes (destructive)

# quick checks (bash; loads .env into the shell first)
set -a; . ./.env; set +a
docker compose exec postgres psql -U mynotes -d mynotes -c "select version();"
curl -sk -u "admin:$MYNOTES_OPENSEARCH_PASSWORD" "https://localhost:${MYNOTES_COMPOSE_OS_PORT:-9200}/_cluster/health?pretty"
```

## OS notes

- **Ubuntu:** OpenSearch needs `vm.max_map_count ≥ 262144`:
  `sudo sysctl -w vm.max_map_count=262144` and persist it in `/etc/sysctl.d/99-opensearch.conf`.
- **macOS / Windows:** Docker Desktop with at least 6 GB of memory (OpenSearch heap + vectors). On Windows use the WSL2 backend; if OpenSearch complains about `vm.max_map_count`, run `wsl -d docker-desktop sysctl -w vm.max_map_count=262144`.
- **Windows team server:** the `mynotes service install` task only runs at logon. For an always-on
  server, wrap the same command in a real Windows service with
  [WinSW](https://github.com/winsw/winsw) or [NSSM](https://nssm.cc/) pointing at
  `<project>\.venv\Scripts\pythonw.exe -m mynotes worker` (use `python.exe` when you want console
  logging). Neither wrapper is generated by `mynotes service install`.

## Disk watermarks

OpenSearch's default disk watermarks are percentages (85/90/95 %). Above the "high" mark it blocks index creation (`cluster create-index blocked`), which happens on large disks that are fairly full even with hundreds of GB free. The compose file therefore uses **absolute free-space** watermarks: low 20 GB, high 10 GB, flood stage 5 GB. Override them with `MYNOTES_COMPOSE_OS_DISK_LOW` / `_HIGH` / `_FLOOD` in `.env`.

If index creation is ever blocked anyway: free space, then clear the block:
```bash
curl -sk -u "admin:$MYNOTES_OPENSEARCH_PASSWORD" -X PUT "https://localhost:9200/_cluster/settings" \
  -H 'content-type: application/json' -d '{"persistent":{"cluster.blocks.create_index":null}}'
```
